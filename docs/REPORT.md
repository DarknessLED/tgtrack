## 0. 三条贯穿全文的结论

1. **检测层：加召回是死路，换"领域匹配的小模型"才是活路。** 六种增召回手段（切片、降阈值、放大模型、原生分辨率、时序累积、双检测器融合）全部实测否决；而把 21.9 M 通用检测器换成 **3.01 M 人体专项检测器**，召回 +7.2 pp、HOTA +0.70 pp、参数少 7.3 倍。
2. **关联层：拒识比匹配更值钱。** 本项目所有真实收益都来自"什么时候不认"——边际检验、搜索侧门控、硬负样本、形状偏差门控，全是拒识机制。
3. **身份的第二证据源几乎不存在。** 自指外观（EMA）、外部 MOT id、姿态、轨迹形状、邻域结构、特征白化，六族全部实测关闭。唯一有效的外部证据是**点击瞬间那张裁剪**——它在失败发生**之前**就被固化。

## 1. 检测层：Recall 从哪来，以及四个陷阱

### 1.1 ✅ 用领域匹配的人体专项检测器替换通用检测器

- **文献**：CrowdHuman（Shao et al., CVPR 2018）；YOLO 系列。
- **用法**：`yolo26m`（通用 COCO，21.9 M，含 person 类）→ `crowdhuman_yolov8n`（人体专项，**3.01 M**）。`configs/ch_det.yaml`，`--imgsz 1280`，`--ignore-regions`。
- **实测**：pooled recall **0.731 → 0.803（+7.2 pp）**；MOT17 HOTA **0.4980 → 0.5050**；MOTA 0.4950 → **0.5586**；IDF1 0.6125 → **0.6531**；49.7 → **41.9 ms/帧**（更快）。
- **为什么**：瓶颈不是表征能力，而是**任务定义**。COCO 的 80 类目标函数把容量分给了非人事物；只做"人"的小网在人体上更专、更快、更准。**参数预算相同甚至更少时，任务窄化胜过模型放大。**
- **启发**：换检测器先问"目标分布一致吗"，而不是"有没有更大的模型"。

### 1.2 ✅ 高分辨率推理（小目标的稳态解法）

- **文献**：SAHI（Akyon et al., ICIP 2022）关于小目标需要更高有效分辨率的论证。
- **用法**：`imgsz 640 → 1280`，单次前向。
- **实测**：pooled recall **0.368 → 0.733**（同检测器，MOT17 5 序列 2658 GT）。
- **为什么**：中景里的人只有几十像素，分辨率是物理下限，不是超参。
- **启发**：**先量目标像素高度**再决定分辨率；否则后面所有调参都在补偿一个物理缺陷。

### 1.3 ❌ 切片推理（SAHI 式 tiled inference）

- **文献**：SAHI（ICIP 2022）；高分辨率小目标检测通行做法。
- **用法**：`scripts/probe_tiling.py`，重叠 0.2、切片 NMS 0.55，扫 1×1/2×2/3×2/4×3，另测 `n@1280` 2×2、`m@640` 2×2。
- **实测**：

  | 设置 | recall | det/帧 | ms/帧 |
  |---|---|---|---|
  | 1×1（基准 1280） | 0.721 | 18.8 | 24.8 |
  | 2×2 | **0.721** | 26.8 | 73.8 |
  | 3×2 | 0.680 | 25.4 | 150.1 |
  | 4×3 | 0.521 | 16.1 | 277.2 |
  | n@1280 2×2 | 0.626 | 23.0 | 68.1 |
  | m@640 2×2 | 0.700 | 23.0 | 52.4 |

- **为什么否决**：切片**不增加信息**，只是把图切碎再放大；边缘目标被切断、上下文丢失。在"目标已 100+ px"的中近景，只换来 3 倍耗时和更多碎片框。
- **启发**：SAHI 的前提是"目标只有十几像素"。**先验证前提**——本例人在 1280 下有 200+ px，前提不成立。切片是给远距离小目标的工具，不是通用提分器。

### 1.4 ❌ 降低置信阈值（为什么阈值换不来 HOTA）

- **文献**：ByteTrack（ECCV 2022）的低分框二次关联动机——低分框里确实有真目标。
- **用法**：`conf 0.25 → 0.01` 六档，先在召回探针量，再在真实管线上量 HOTA。
- **实测**（召回探针，MOT17-02）：

  | conf | recall | det/帧 |
  |---|---|---|
  | 0.25 | 0.721 | 19.1 |
  | 0.15 | 0.775 | — |
  | 0.10 | 0.797 | — |
  | 0.05 | 0.840 | — |
  | 0.02 | 0.883 | — |
  | 0.01 | **0.911** | **95.8** |

  真实管线（7 序列，subsample 3，200 帧）：tracktrack HOTA 0.5038 → 0.5022（**−0.16 pp**）；bytetrack 0.5037 → 0.5072（+0.35 pp）。
  **边际精度** 244/(244+197) = **0.553**。
  另有陷阱：`conf 0.05` 与 `0.10` **逐位相同**——跟踪器 `track_low_thresh=0.1` 是硬地板，有效阈值 = `max(detector.conf, 0.1)`。
- **为什么否决**：HOTA 是 `DetA×AssA` 的几何平均，DetA 同时罚漏检与虚检。召回 +19 pp 同时虚检 ×5，两者抵消。**过了某个点，召回不再是瓶颈，精度才是。**
- **启发**：调阈值前先算**边际精度**；< 0.6 时降阈值必然被虚检吃掉。另外**先查跟踪器自己的低分地板**，否则以为调了其实没调。

### 1.5 ❌ 放大通用检测器 / 原生分辨率

- **用法**：`yolo26l@1280`（53 MB）、`imgsz 1920`。
- **实测**：`yolo26l@1280` pooled recall **0.707 < yolo26m 0.733**；逐序列 5 个里 1 赢 2 输 2 平。`imgsz 1920` 六档阈值**逐点更差**（0.687 vs 0.721 …）。
- **为什么否决**：COCO 上的"大模型更准"是针对 80 类平均；对人这一类，额外容量没转化为召回，反而更依赖全局上下文。原生分辨率则引入**训练分辨率失配**。
- **启发**：**"更大"和"更高分辨率"都不是单调增益**，必须按任务分布实测。换人体专项小模型（1.1）比放大通用模型划算。

### 1.6 ❌ 双检测器框级融合（union 召回 ≠ HOTA）

- **文献**：集成经验；WBF（Solovyev et al., 2021）。
- **用法**：`DetectorCfg.extra_weights` + `fuse_detections()`（NMS 0.55），`configs/ch_fused.yaml` = yolo26m 主 + CrowdHuman 副。
- **实测**：

  | 配置 | HOTA | MOTA | IDF1 | ms/帧 |
  |---|---|---|---|---|
  | yolo26m 单独 | 0.4980 | 0.4950 | 0.6125 | 49.7 |
  | CrowdHuman 单独 | **0.5050** | **0.5586** | **0.6531** | 41.9 |
  | 融合（union recall **0.830**） | **0.4944** | 0.4954 | 0.6268 | **89.2** |

- **为什么否决**：两器失败集合确实不同（union 比最好的单模型高 2.7 pp 召回），但融合带来大量重复/松框，DetPr 掉的比 DetRe 涨的多，**净 −1.1 pp**、耗时翻倍。
- **启发**：**"圆召回"是错的目标函数。** 若新框与旧框半重叠，NMS 后仍是两框；融合必须配"框质量判别器"，而不是简单 NMS。

### 1.7 ❌ 跨帧时序累积（SPRT / track-before-detect）

- **文献**：Wald SPRT（1945）；track-before-detect；低分检测时序验证。
- **用法**：`src/tgtrack/promote.py` 的 `TemporalPromoter`（`p_hit_true 0.7 / p_hit_false 0.15`、`alpha 0.05 / beta 0.3`、`max_age 5`），`scripts/probe_promote.py --conf-lo 0.05`。
- **实测**：`promoted 437`、`promoted_tp 88` → **精度 20.1%**；对照"直接信任低分框"是 **55.3%**。SPRT 把精度从 55% 主动降到 20%。
- **为什么否决**：似然来自"跨帧一致性"，而视频里**最跨帧一致的是静态背景**（栏杆、广告牌、停车）。它在"低分框里哪些是真"上选出的是背景。
- **启发**：**时序一致性先验必须配"这是不是人"的先验。** 不要用"持续出现"代替"外观可信"。

### 1.8 ✅ 先诊断损失发生在检测还是关联（避免修错地方）

- **用法**：`scripts/probe_gating.py` 把 GT 与"检测器原始输出"、"跟踪器上报框"分别比对。
- **实测**：MOT17-02 上报召回 0.527 vs 检到 0.556（**门控损失 2.9 pp**）；MOT17-04 0.729 vs 0.738（**0.9 pp**）。
- **为什么重要**：把"召回只有 0.53"从"跟踪器丢框"证伪为"检测器上限"，直接避免了继续在关联层投入。
- **启发**：端到端指标出问题，第一件事做**逐段归因**（检测/门控/关联/输出）。

## 2. 关联与身份判定（核心战场）

### 2.1 ✅ 两阶段级联关联（几何粗筛 → 外观精算）

- **文献**：级联分类器（Viola & Jones, CVPR 2001）；MOT 的代价分层实践。
- **用法**：`TargetTracker._associate` 第一段只几何（`compute_costs` 不带外观），得 `(icost, acost)`；只有进 `per_icost` 窗口或总代价前 3 的才进第二段做编码。
- **实测**：编码器占墙钟 **79%**；两阶段后可自适应"一个都不编码"。配合 6.1/6.2，单目标层 **351.6 → 201.0 ms/帧（−42.8%）**，40 帧 A/B **决策 0/40 改变**。
- **为什么**：8 GB 卡上"每帧 20 人×5 部件编码"不可行（107 ms/帧起且会 OOM），而绝大多数帧、绝大多数检测与目标无关。
- **启发**：**先算最便宜的代价用于剪枝**；级联的收益在预算不在精度。阈值要写成"相对最优候选的窗口"，不能写绝对值，否则目标整体偏移时会全剪掉。

### 2.2 ✅ 边际检验 / 拒识（`distractor_margin`）——收益最大的一条

- **文献**：distractor-aware tracking（Deep OC-SORT, CVPR 2023 W 的 proximity/appearance gate）；开放集识别的拒识思想。
- **用法**：`cost.distractor_margin = 0.06`：最优必须比次优好至少这个量，否则**拒绝关联**（宁可报丢失）。
- **实测**（dev 三序列 pooled，`mask=none`）：

  | margin | pooled TSR | 说明 |
  |---|---|---|
  | 0.00（关） | **0.121** | 0007 上 0.030，几乎立刻换人 |
  | 0.04 | 0.325 | 仍差 |
  | **0.06（采用）** | **0.450** | 峰值 |
  | 0.08 | 0.430 | 开始过度拒识 |
  | 0.12 | **0.086** | 几乎一直在拒绝 |

- **为什么采用**：消费者跟踪器最典型的失效不是跟丢，而是**悄悄换人**（静默错误，操作员发现不了）。边际检验把"有歧义"变成"明确的丢失"，把静默错误转成可观测事件。
- **启发**：当超参最优值表现为**尖峰**而非平台时，它编码的是"正确性条件"而非"平滑偏好"。这类参数要**先讲清语义再取值**，不能靠 grid 趟过去。

### 2.3 ✅ 搜索侧身份门控（`search_margin`）

- **文献**：长时跟踪 lost-rebind（GlobalTrack, AAAI 2020；TrackTrack/CVPR 2025 的 `lost_match_thr`，官方默认 0 即关闭）。
- **用法**：`cost.search_margin = 0.20`，"搜索/重捕获"阶段额外要求最优领先次优 ≥0.20，且该阶段**要求外观证据可用**（禁止纯几何重认）。
- **实测**：dev FAR **0.258 → 0.197**，TSR 0.554 → 0.544（−1.0 pp）；MOT17 与 held-out 无回归。（dev 数字后来被证明不可外推，见 5.3。）
- **为什么**：错误身份在**重捕获**时产生（E063 逐帧证据：114/116 个错误帧发生在 tracking 状态，但**起点**是一次搜索），所以加严搜索侧比加严跟踪侧更对症。
- **启发**：**防御要加在"身份被决定的瞬间"**。跟踪阶段的错误是搜索阶段的后果。

### 2.4 ✅ 硬负样本库（IoU 上限 0.30 + 容量 8）

- **文献**：hard negative mining（FaceNet, CVPR 2015 传统）；开放集 ReID 的"记住相似但不同的人"。
- **用法**：`memory.hard_negative_bank = True`、`hard_negative_capacity = 8`、`hard_negative_max_iou = 0.30`：与目标外观距离 ≤ `CONFUSABLE_DIST 0.35` 且与目标框 **IoU ≤ 0.30**（必须是另一个框）的检测记为硬负样本，匹配时惩罚。
- **实测**（dev，`mask=none`）：关库 TSR 0.450 → `max_iou 0.30` **0.475**（FAR 0.328→**0.312**）→ 容量 8 **0.512**（id_consistency 0.279→**0.444**）；`max_iou` 0.5/0.7 单调退化（0.375/0.386）；容量 4/16/32 = 0.477/0.475/0.475。
- **为什么**：外观相似的行人是换人的直接原因，把它们记为显式负证据比让阈值泛化更可靠。**IoU 上限是关键**：没有它，目标自己另一帧的裁剪会被当成负样本（自伤）。
- **启发**：负样本挖掘两处最容易错——**把目标自己挖成负样本**（用 IoU 上限防住），**容量无限增长**（会在留出集上纯过拟合，见 5.3）。容量 8 是本项目最不稳健的旋钮。

### 2.5 ✅ 自适应身份带（点击锚点 + MAD）

- **文献**：MAD（Rousseeuw & Croux, 1993）；conformal prediction 的"用校准分布定阈值"（Angelopoulos & Bates, 2021）。
- **用法**：`cost.anchor_adaptive = True`：以**点击瞬间裁剪特征**为锚，记录"被接受目标与锚的距离"序列，取 `median + k·1.4826·MAD`（k=2.0，窗口 64，冷启动最小 8）。
- **实测**：本项目第一个**严格 Pareto 改进**（TSR 涨、FAR 不涨），成为后续旋钮组合的基础。
- **为什么**：固定阈值把"相机/人/衣服的成像质量"和"身份是否可信"混为一谈；用目标自身分布定标，阈值随光照/尺度/姿态自动缩放。
- **启发**：**阈值应由被判断对象的自身统计量决定**，而非全局常数。工程上等价于"每目标在线校准"，成本极低（几十个标量）。

### 2.6 ✅ 部件感知长时图库 + 形状偏差门控（部分视图的真正来源）

- **文献**：part-based ReID（PCB, ECCV 2018；MGN, ACM MM 2018）；遮挡 ReID 基准 PRCC（ICCV 2021）、Occluded-Duke（ICCV 2019）。
- **用法**：图库按 `full/upper/lower/head/torso` 分库；查询↔库部件亲和度由**几何重叠度**给出；融合按部件**可信度**加权，且只在 `partial_fusion_shape_dev ≤ 0.45`（相对点击框的形状偏差）时启用。
- **实测**：
  - 机制证据（下半身遮挡）：`cos(full)=0.757`，而 `cos(upper)=0.920`、`cos(head)=1.000`、`cos(torso)=0.941`、`cos(lower)=0.429`；旁人 `upper=0.48`。**整身只到 0.757，部件查询把同类拉到 0.92、异类推到 0.48。**
  - 检索精度（上半身查询命中）：**0.672 → 0.855**。
  - 受控同轮 TSR（MOT17-02，target 19，上半身掩码）：**0.7818 → 0.8545（+7.27 pp）**；分部件 `none −0.63 / lower +2.50 / head +9.00 / upper +7.90 / torso +0.52 pp`。
- **为什么**：需求"只露一部分也要能跟"在**整身描述子框架下无法实现**——遮挡改变的是可见区域，不是身份。必须让描述子与"哪部分可见"对齐。
- **启发**：融合前先确认"这真是部分视图"。第一版没有形状偏差门控，在 DanceTrack（几乎无遮挡）上 TSR 从 0.675 崩到 0.180——**机制在没有触发条件的场景里变成噪声源。**

### 2.7 ✅ 运动学速度钳制（把阈值写到物理量上）

- **文献**：NSA Kalman（GIAOTracker, arXiv 2102.09162）的置信度自适应噪声；长时跟踪的尺度有界先验。
- **用法**：`motion.velocity_clamp_ratio = 3.0`、`velocity_clamp_floor = 2.0`：把状态速度钳在 `k×观测速度` 与 `k×身高/帧` 之间。
- **实测**：上半身掩码 TSR **0.7527 → 0.7818（+2.91 pp）**，`none` 掩码 0.9236 → 0.9200（−0.36 pp）。
- **为什么**：部分视图下检测框高只剩一半，若把速度换算成"每秒像素"就会得到翻倍速度，滤波器随后发散。钳制提供硬护栏。
- **启发**：**阈值要写在物理量纲上**（身高比例/帧），不要写在归一化量纲上；否则透视或裁剪一改就失去意义。这也是 3.7 那个 bug 的根因。

### 2.8 ⚠️ 冻结点击裁剪作为身份天花板（有效但有序列依赖）

- **文献**：one-shot / 开放集 ReID；"锚点不随跟踪漂移"的工程经验。
- **用法**（`cost.click_ceiling_iou = 0.65`，未设为默认）：以点击裁剪为唯一不可污染参考，超阈值即判"不是目标"。
- **实测**：0007 TSR **0.401 → 0.485**、FAR **0.435 → 0.210**；但 0004 TSR **0.265 → 0.155**（FAR 不变）；pooled dev **0.554 / 0.265**。限制在搜索侧的版本更差（0007 0.315/0.665）。
- **为什么只当局部手段**：它用"一个样本"定义整个人，对**外观会变**的序列过严，对**外观稳定但旁观者相似**的序列极有效。
- **启发**：单锚点天花板是"高精度/低召回"的选择，**适合当旋钮不适合当默认**。它的价值是证明了**冻结锚点是有信息的**——这正是 2.14 的对照。

### 2.9 ❌ 姿态/骨架作为身份证据

- **文献**：GAE-Net（Neural Networks 2025，步态辅助视频 ReID）；长周期 ReID 中"步态优于外观"（Pattern Recognition 2025）。
- **用法**：`scripts/probe_pose_identity.py`，yolo26-pose 17 关键点归一化到包围盒，算同人/异人 AUC，并与 ReID 描述子加权融合。
- **实测**（AUC）：

  | 序列 | app_full | app_upper | pose_full | pose_upper | 融合 |
  |---|---|---|---|---|---|
  | MOT17-02 | 0.974 | 0.982 | 0.725 | 0.765 | **0.951** |
  | DanceTrack-0004 | 0.593 | 0.583 | 0.478 | 0.439 | 0.538 |
  | DanceTrack-0005 | 0.669 | 0.649 | 0.325 | 0.318 | 0.470 |

  融合最高 0.9505 < 单用 `app_upper` 0.9824；且 `app_upper ≥ app_full`，说明**部分视图的难点不在外观，而在几何**（与 2.6 一致）。
- **为什么否决**：**单帧静态骨架不含身份信息**——步态身份需要跨帧周期（关节相位），单帧只编码"现在在做什么动作"。DanceTrack 是舞者，姿势分布本身在变，AUC 掉到 0.44（低于随机）。
- **启发**：引用文献结论要看清**设定**：步态 ReID 的前提是"跨帧序列 + 受控行走"。跨领域借鉴必须验证前提，否则只是迁移了名词。

### 2.10 ❌ 轨迹形状描述子（转弯率/加速度）

- **文献**：IMM 与机动目标跟踪的转弯率模型（见 3.1）。
- **用法**：`src/tgtrack/trail.py`：`trail_steps=8`、`trail_len=16`，2×steps 维 `[log1p(速度/身高), 转向角/π]` 描述子做余弦距离，`cost.trail_weight` 扫 0.5/1.0/2.0。
- **实测**：0004 TSR **0.415 → 0.095**（FAR 0.040 → 0.115）；0007 上**完全惰性**（所有 weight 逐位相同——该代价只在搜索时生效，而 0007 的失效从不经过搜索）。
- **为什么否决**：拥挤场景里候选轨迹段的局部形状主要反映"谁挤在谁旁边"，与"我走过的路线"无关；样本太长时目标自身机动噪声淹没形状差异。
- **启发**：轨迹形状是**弱信号且强局部**，要用必须配"机动检测"（先用 IMM 判断是否在机动，再决定是否信任形状）。另外**先确认机制会被触发**。

### 2.11 ⚠️ 管道速度航向一致性（机制对，但代价是交换）

- **文献**：光流/运动一致性用于身份验证；"邻居共同运动"先验。
- **用法**：`cost.tube_velocity_weight`：用 arena 全体轨迹给每个检测算局部管道速度（周围三帧邻居中心平均位移），与目标速度做 `0.5·(1−cos)` 一致性代价。
- **实测**：0007 FAR **0.595 → 0.275（−32 pp）**、TSR 0.426 → 0.371（−5.5 pp）；0004 TSR **0.415 → 0.220**（−19.5 pp）。**总账是交易，不是改进。**
- **为什么没采用**：它的假设是"目标与邻居运动一致"——人群**同向行走**成立，**交叉拥舞**不成立，而 0004 是后者。
- **启发**：**"机制在被测序列上有效"不等于"机制正确"**。先写清它依赖的物理假设（同向流），再挑假设成立的子集验证。

### 2.12 ❌ 外观引导的全员关联（ReID-in-MOT）

- **文献**：BoT-SORT（arXiv 2206.14651）、StrongSORT（TMM 2023）、Deep OC-SORT（CVPR 2023 W）；ultralytics `with_reid` 开关。
- **用法**：先试 `with_reid: True`（**逐位相同**——空开关，`--no-embed` 让特征没传播）；再用真实特征做 `appearance_gate=True` 对照（E066）。
- **实测**：`AssA` **+0.015 pp（botsort）/ −0.068 pp（tracktrack）**，帧耗时 4.9 → 57.4 ms（**11.7×**）；特征确实送达（14,400 行 / 400 帧 / 最多 60 条轨迹）。
- **为什么否决**：同着装场景外观判别力本就弱（AUC 0.59–0.67，见 2.9）；MOT17 上外观好但收益被检测噪声吃掉。**11.7 倍代价，收益在噪声内。**
- **启发**：**先证明开关不是空的**（本项目最贵的一次空开关）；带 `--no-embed` 这类默认陷阱的管线，"开关无变化"必须首先查默认值。

### 2.13 ❌ 外部 MOT 层 tracklet id 作为第二意见

- **文献**：BoT-SORT/TrackTrack 的轨迹级身份实践；MOT 中的 tracklet-confidence。
- **用法**：`scripts/probe_tracklet_evidence.py`：丢失期间若某 MOT id 的框与丢失框 **IoU ≥ 0.5** 且末尾 5 帧全为它，则判"外部确认"。
- **实测**：丢失帧中 **84.4%** 存在 IoU ≥ 0.5 的 MOT 框；但 ≥5 帧丢失段里被**单 id 端到端锚定**的仅 **6/14 = 42.9%**，帧覆盖 **108/1113 = 9.7%**；**五个 ≥50 帧长丢失全部未锚定**。MOT id 在"已成功处"很稳定（中位单 id 连续 **103 帧**），在"失败处"每 2–3 帧断一次。
- **为什么否决**：**与需求反相关**——它稳定时我们不需要，我们需要时它不稳定。
- **启发**：借用"外部裁判"要测它在**我们需要的那个子集**上的可靠性；整体 84% 掩盖了关键子集 0% 的可用性。

### 2.14 ❌ 双见证审计（click 锚点 + 近期 EMA）——最锋利的一条教训

- **文献**：多假设跟踪的双证据一致性（MHT/JPDA）；conformal 的多重校准。
- **用法**：`audit_interval=3`、`audit_margin=0.05`、`audit_persist=2`：tracking 状态下用"click 锚点距离"与"近期 EMA 距离"两个见证联合判断是否切换。
- **实测**：
  - 单独用 click 锚点（E063）：0007 TSR **0.426 → 0.629（+20.3 pp）**、FAR **0.595 → 0.375**；但 0004/0005 上 **−28 pp / −20 pp**，故未上线。
  - 加入第二个见证后：**逐位精确的空操作**——所有 40 帧的审计帧数都是 0。
  - 根因：`stm.current()` 是**已接受裁剪的 EMA**。一旦跟错，**它就是那个冒名者**。它否决了本来正确的切换：0007 **31/31**、0005 **23/23**、0004 **16/17** 次（边际中位数 −0.1445 / −0.1986 / −0.0613）。
- **为什么否决**：**自指参考无法为自己作证。** 该参考在它要检测的失败**之后**才写下来，因此永远与失败同向。
- **启发**（可迁移判据）：**"这个参考会在它要检测的失败发生之前被写下吗？"** 若否，实验作废。合法参考只有两种：**失败之前捕获的**（点击锚点）、**来自被跟踪者历史之外的**（外部检测器/场景先验）。

### 2.15 ❌ 特征白化 / 去相关

- **文献**：ReID 的 PCA 白化（Luo et al., 2019 "Bag of Tricks"）；跨域 ReID 的相关性对齐。
- **用法**：`scripts/probe_embed_metric.py`，在 click 裁剪+同人/异人样本上估协方差，白化后重算 AUC。
- **实测**：DanceTrack AUC **0.75 → 0.55**；MOT17 **0.97 → 0.69**。**白化破坏了判别力。**
- **为什么否决**：这个小特征空间（512-d，来自 9.8 MB ONNX）里，"共同方向"承载的就是身份信号，白化把它当噪声压掉了。
- **启发**：**降维/白化是"去冗余"，前提是存在冗余。** 小模型小特征上先验证"主成分是不是身份方向"，否则等于自毁。

### 2.16 ❌ 邻域人际结构（相对位置拓扑）

- **文献**：社会力模型（Helbing & Molnár, 1995）；人群 ReID 的上下文建模。
- **用法**：`scripts/probe_neighbour_identity.py`：目标与最近 5 个邻居的相对位置极坐标编码，测 AUC。
- **实测**：AUC **0.333**（低于随机 0.5）。
- **为什么否决**：人群结构是**流动的**，几十帧内邻域就换人；把它当身份会引入反向证据。
- **启发**：**"人总成群出现"是场景统计，不是身份特征。** 拓扑先验适合做空间先验，不适合做身份判据。

## 3. 运动模型

### 3.1 ✅ IMM（匀速/匀加速/匀转弯三模型交互）

- **文献**：Blom & Bar-Shalom（1984）；Bar-Shalom & Li, *Estimation and Tracking*（1993）。
- **用法**：`motion.model = "imm"`，模型集 `("cv","ca","ct")`，`imm_stay_prob = 0.85`；8 维状态 `[cx/h, cy/h, w/h, h, ẋ, ẏ, ẇ, ḣ]`（中心按身高归一化）。
- **实测**：匀速 40 px/帧时预测误差在 20 帧处 **IMM −7.46 px vs 单 KF −13.28 px**（约 2× 快）；100/300 帧两者都收敛到 **0.00**。非线性：曲线误差比单 KF **低 25%**，匀加速 **低 61%**。
- **为什么采用**：需求④要求处理非线性运动，单 CV 模型在转弯/急停时系统性滞后。
- **启发**：**IMM 的收益主要在"机动瞬间"**，匀速段与 KF 无差别。另外**冷启动预测滞后与速度成正比**（40 px/帧时前 20 帧落后 13 px），门控必须容忍这个滞后，否则一开始就因"预测不准"而拒识。

### 3.2 ✅ NSA 自适应噪声（按检测置信度缩放观测噪声）

- **文献**：NSA Kalman（GIAOTracker, arXiv 2102.09162）。
- **用法**：`motion.nsa_adaptive = True`：`R = R0 / conf`。
- **实测**：随 3.1 的 A/B 验证，非线性段误差进一步下降；检测置信度波动大的序列更稳。
- **为什么采用**：检测器在遮挡/小目标上给出的低分框**系统性偏移**，把它的噪声等同高分会让滤波器被坏观测拖走。
- **启发**：**置信度不只是"用不用"的门限，还是"信多少"的权重**；把两者分开比单一阈值有效。

### 3.3 ✅ 观测中心回滚（OCM/ORU 类）

- **文献**：OC-SORT（Cao et al., CVPR 2023）的 Observation-Centric Momentum/Recovery；FastTracker（arXiv 2508.14370）的遮挡回滚（覆盖 > 0.7 时回退 3 帧位置、5 帧速度、高度 ×1.1、速度 ×0.5）。
- **用法**：`motion.rollback_depth = 5`、`coast_velocity_damp = 0.98`：检测尺寸/位置跳变时回滚状态并衰减速度。
- **实测**：遮挡恢复段的位置跳变显著减少；配合 3.4 的门控修复，长时重捕获才真正可用。
- **为什么采用**：遮挡期的预测是"想象出来的"，拿它当基准会把后续关联全部拉偏。
- **启发**：**"最后观测"比"当前预测"可信。** 长时跟踪必须区分"我知道的"（观测）与"我猜的"（预测），猜久了就降低权重。

### 3.4 ✅ 门控半径归一化 + 盲区冻结（两个真实 bug）

- **问题**：门控半径曾写成**裸像素**，长时丢失（fsu>60）后半径饱和，**全局搜索被永远门掉**，重捕获在结构上不可能。
- **修法**：`StateCfg.gate_growth_by_frame_diag`：半径 = `base×帧对角线 + speed_gain×预测速度`；`lost_short` 起**冻结速度增长**并开启全局搜索。
- **实测**：修复后"全局搜索"才真正发生——这是长时重捕获能被测量的前提。
- **启发**：门控半径必须是**尺度无关量**，且**丢失期间必须停止信任速度**。这两条都是"看起来自洽、实际永远不触发"的典型 bug。

### 3.5 ❌ 形状先验（宽高比 / 尺度边界）

- **文献**：行人宽高比先验（约 0.3–0.45）；tracklet 形状一致性。
- **用法**：`motion.shape_prior = True`，比例 0.60/1.70，尺度 0.60/1.90。
- **实测**：上半身掩码 **0.7527 → 0.7345（−1.8 pp）**；`none` 0.9236 → 0.9290（+0.5 pp）。**总体为负，默认关闭。**
- **为什么否决**：部分视图下"半身框"的宽高比**本来就不是行人比例**，形状先验在这里恰好是错的。
- **启发**：**先验越强，越要检查它在目标工况下是否成立**——行人比例先验在"只看上半身"时直接失效。

### 3.6 ❌ 运动带自适应（用自身运动历史定 Mahalanobis 带）

- **用法**：把 2.5 的"锚点+MAD"搬到运动轴。
- **实测**：`baseline` vs `band_2.0` **20 个配对里 17 个联合位移恰好 0.000**；剩余 3 个方向错误。
- **为什么否决**：与 2.5 同构，但**运动轴可分性远低于外观轴**——遮挡已由 3.4 处理，再叠一层只把两类错误混在一起。
- **启发**：**同一个统计技巧不能假设在每个轴上都有同样信噪比。** 外观轴 AUC 0.97，运动轴在遮挡下几乎不可分。

### 3.7 ⚠️ 状态空间单位一致性（必须写进检查清单的 bug 类）

- **Bug**：状态中心按身高归一化（`cx/h`,`cy/h`），但过程/观测噪声仍按 DeepSORT 的**绝对量纲**构造（`std = w·h`），归一化分量的噪声被放大 **240 倍标准差（57,600 倍方差）**。
- **后果**：`mahalanobis()` 完全失效——300 px 偏差只得 0.0036（门限 9.4877），**任何检测都能过门控**。
- **修法**：中心噪声 `std=w_p`，身高噪声 `std=w_p·h`，宽高比 `1e-2`。
- **启发**：**归一化的状态空间必须配归一化噪声。** 这类 bug 不报错，只让门控变摆设。检查法：**用极端输入验证判据**（打个 300 px 外的离谱检测，看代价是否真的很大）。

## 4. 记忆与时间尺度

### 4.1 ✅ 双时间尺度（短期 EMA + 长期图库）

- **文献**：StrongSORT（TMM 2023）的 AFLink/GSI；长时 ReID 的 gallery 维护。
- **用法**：`ShortTermMemory`（EMA `stm_alpha=0.9`，环形 64 帧）+ `LongTermGallery`（容量 96、多样性 0.15、最低质量 0.35、半衰期 600 帧、质量-时新替换）。
- **实测**：长时图库是部分视图能力的载体（2.6）；短期 EMA 在稳定外观下提供低延迟强判别，但在跟错后变成自指毒药（2.14）。
- **为什么**：两个尺度解决两个问题——EMA 抗噪声、图库抗外观漂移。
- **启发**：**短期记忆只能用来"平滑"，不能用来"作证"**；任何把 EMA 当身份判据的设计都会在换人后自我强化。

### 4.2 ⚠️ 半衰期（时间衰减）——600 是地板，不是最优点

- **用法**：`ltm_half_life` 扫 150 / 300 / 600 / 4800 / none。
- **实测**：150 明显差（0007 `none` TSR **0.436 → 0.325**，FAR 0.436 → 0.468）；300 **与 600 逐位相同**；4800 与 none 相同。
- **为什么保留 600**：时间衰减是"防图库被旧样本锁死"的护栏，主要对循环视频有用；200–300 帧序列上 `λ=ln2/600` 基本不衰减。
- **启发**：**很多"消融有效"的超参实际在测"有没有护栏"，而不是"护栏多长"。** 300 与 600 逐位相同时，不能写成"600 最优"。

### 4.3 ❌ 自适应遗忘（半衰期随漂移自适应）

- **用法**：`ltm_adaptive_half_life`，漂移超阈值（0.25/0.30/0.35）切快半衰期（150）。
- **实测**：0004 上三个阈值**全部与基线逐位相同**；0007 上 0.25/0.30 **更差**（FAR +0.14/+0.15），0.35 同基线。
- **为什么否决**：漂移量**由图库自身与 EMA 的关系定义**，再次是自指参考（2.14）；"真漂移"与"换人"被混成同一信号。
- **启发**：自适应机制若以自指量为输入必然**不可分**；要自适应，输入必须来自外部（置信度、可见度、场景变化）。

### 4.4 ❌ 图库卫生（质量门 / 容量）作为增益

- **用法**：`gallery_hygiene` 组：`ltm_min_quality` 0.0/0.30/0.50/0.70；容量 24/96/240。
- **实测**：质量门**全惰性**（0.30=0.50=0.70 与关闭逐位相同）；容量不变。唯一有效的是 2.4 的**硬负样本 IoU 上限**。
- **为什么否决**：该数据分布下被接受的裁剪质量都高于门槛，质量门从不触发。
- **启发**：**先确认机制被触发（计数器），再解释"无变化"。** 惰性消融有两种解释：机制有害，或机制没开——这里全是后者。

### 4.5 ❌ 固定点击锚点常驻图库（"永不遗忘的锚点"）

- **用法**：`ltm_anchor_count = 4`：图库中固定保留点击时刻的 4 个裁剪，永不淘汰。
- **实测**：锚点 4/16/32 三变体**全部与基线逐位相同**（0007 TSR 0.436/FAR 0.435）；锚点 32 才变差（0.325/0.705）。
- **为什么否决**：200 帧运行里图库**根本没轮转过**——容量 96 从未填满，淘汰从未发生。于是"保护锚点"是在保护一个**不存在的机制**。
- **启发**：**"永不遗忘"只在会发生遗忘的尺度上才是特性。** 做长期记忆实验前先量"图库填满需要多少帧"。

### 4.6 ✅ 盲区冻结外观记忆

- **用法**：进入任一盲态（`occluded_soft/lost_short/lost_long/out_of_frame`）时，图库与 EMA **停止吸收**新裁剪。
- **实测**：这是"跟丢后不越陷越深"的前提，也是 2.14 那条自指教训的**唯一正确用法**——冻结不是为了作证，而是为了**不让污染扩散**。
- **启发**：**记忆的正确用法是"记录我确信的"，不是"记录我最近看到的"。** 盲区里看到的往往是遮挡者。

## 5. 评测方法（这部分翻转过我们自己的结论）

### 5.1 ✅ 采用 MOT 官方 ignore 区域约定

- **文献**：MOTChallenge 评测规则；TrackEval（Luiten et al., HOTA, IJCV 2020）。
- **用法**：`--ignore-regions`：与 ignore 区域（标签 conf=0 的人群/镜像/车辆）IoU ≥ 0.5 的预测框**不计 FP**，但永远不会让非法预测算成 TP。
- **实测**（同一份已保存轨迹离线重算）：HOTA **0.4856 → 0.4980（+1.24 pp）**；DetA 0.4398 → 0.4609；DetPr 0.6862 → 0.7403；MOTA 0.4398 → **0.4950**；CLR_FP **4,128 → 2,572（−1,556）**；CLR_FN 不变。
- **为什么**：不采用就是**用错误的评测打自己**——模型在人群区域给出合理框会被当作假阳性。
- **启发**：**先对齐评测公约数，再比方法。** 这一条比多数算法改进都值钱（+5.5 pp MOTA）且完全免费。

### 5.2 ✅ 自研 HOTA 并与 TrackEval fixture 对拍

- **用法**：`src/tgtrack/evaluate.py` 从零实现 HOTA/MOTA/IDF1/AssA/DetA/LocA，用 TrackEval 公开 fixture 逐序列对拍。
- **实测**：对拍中发现自己的 `AssA` 组合方式有 bug（平均权重用错），修复后与参考实现一致。
- **启发**：**自研指标必须对拍参考实现**，否则所有结论都建在私有口径上。

### 5.3 ✅ 留出集 + cluster bootstrap（推翻了本项目头号结论）

- **文献**：cluster bootstrap（Efron & Tibshirani, 1993）；按序列分组重采样。
- **协议**（`docs/METHOD.md`）：按训练/验证切分后留出整段验证序列；**冻结 dev**（dancetrack0004/0005/0007）只选参；留出 22 序列只报告；区间 2000 次按序列重采样。
- **实测**：

  | 量 | dev (n=3) | 留出 (n=22) | 95% CI |
  |---|---|---|---|
  | TSR | **0.512** | **0.2102** | **[0.1154, 0.3253]** |
  | FAR | 0.280 | 0.2364 | [0.1419, 0.3391] |

  dev 的 0.512 **落在留出集 CI 之外**——dev 不是"乐观"而是**不可外推**。dev n=3 的 CI 半宽 **±0.394（TSR）/±0.708（FAR）**，从来无法区分任何两种策略。留出分布**双峰**：中位 0.153，**7/22 序列 TSR < 0.05**，2/22 > 0.80。
- **为什么这么做**：7 个上线旋钮**全部**"在 dev 选、在 dev 报"，选择与报告 100% 重叠。
- **启发**：**样本数少于 10 的均值差值不是结论。** n=3 上的 +20～30 pp 在 n=22 上变成 0 或负。要选参的数据不能用来报告。

### 5.4 ✅ 真值与掩码的正确性（两次结论撤回的根因）

- **Bug 1**：探针用 `seq.gt_at(i)[0]` 当真值——那是"该帧任意一个人"（内部稠密 id），**不是目标**。对齐后：113 个错误帧里 **108 帧目标其实被检测到了**。
- **Bug 2**：两管线对比没做逐帧对齐验证，差点得出"新版差 30 pp"（实际是 GT 索引错位 + 自动选了不同 target id）。
- **启发**：**真值取值必须走唯一入口**（`make_target_gt(seq, target_id)`），**每次跨管线对比都要验证逐帧对齐**（用 GT 与检测的对应关系做滞后检验）。这类 bug 不报错，只会让结论刚好反过来。

### 5.5 ✅ 多重比较预算

- **实测**：整个 campaign **905 次运行 / 96 个变体 / 514 个指标②单元格**；α=0.05 下即使全无效也会产生约 **3.5 个假阳性**。
- **对策**：统计单元改为 `(spec, sequence)`；每变体至少 8 个序列；上线前先算清"这个结论经过多少次比较"。
- **启发**：**调参次数本身会制造"进展"。** 记录总运行数与搜索空间大小，与记录结果同等重要。

### 5.6 ✅ 空开关必须用计数器证明

- **实测**：`with_reid: True/False` **逐位相同**；原因不是"ReID 无效"，而是 `eval_mot.py` 默认 `--no-embed`，特征没传播。加特征计数后才看到真相（14,400 行 / 400 帧 / 最多 60 条轨迹）。
- **启发**：**任何"无变化"的消融，先证明机制真的运行了。** 带默认值的管线（`--no-embed`、`--ablate all`）上，"开关无效"与"开关没接上"外观完全一样。

### 5.7 ✅ "逐位相同"必须逐元素验证

- **实测**：性能优化被评审断言"bit-identical"；逐元素比对后 `max|Δ| = 3.00e-4`——把 4 个裁剪拼成 12 个批量前向时，CUDA 卷积的批形状改变了累加顺序。**决策 0/40 改变，但数值不完全相同。**
- **启发**：**"决策不变"与"数值逐位相同"是两件事**，报告不能混用。

### 5.8 ✅ 多方向外部审计

- **做法**：每循环派 4–5 个独立 subagent，分别审**指标真实性/探索方向/方法严谨性/性能**，要求逐条复算并给证据路径。
- **实测**：24 条声明复算结果 **OK 12 / 过期 4 / 错误 6 / 无支撑 2**。错误包括：把"部分视图 +10.18 pp"当受控结果（实为跨 epoch 相减）、"3.6 pp 代价"写成有对照（实际没有）、一个掩码单元格抄错数值。
- **启发**：**自己审自己必然漏。** 让"没有上下文包袱"的审计者复算数字，是本项目发现自身最严重错误的方式。

## 6. 性能工程（可以"白拿"的改动）

### 6.1 ✅ 消除重复编码

- **问题**：`_features_for` 把 `_ensure_features` 刚算过的框**又算一遍**（94 ms/帧，占墙钟 33%）。
- **修法**：一次编码 + 结果复用（`_encoded_dets` 缓存 + 部件复用）。
- **实测**：单目标层 **351.6 → 201.0 ms/帧（−42.8%）**，编码器 196.9 → 59.9 ms（**3.3×**）；40 帧 A/B **决策 0/40 改变**。

### 6.2 ✅ 绕过 ORT 的 Python 包装，直调 `session.run`

- **用法**：直接构造输入 dict 调 `onnxruntime.InferenceSession.run`，跳过逐 crop 循环。
- **实测**：编码器 3.3× 降低；`max|Δ| 3.0e-4`（见 5.7）。
- **启发**：**推理耗时的大头常在上层胶水，不在算子。** 剖析先看"每 crop 的 Python 开销"。

### 6.3 ⚠️ 并行度与 8 GB 显存的硬约束

- **实测**：4 worker **3.92×**（1452.9 → 370.7 s）；2 jobs **2.00×**（DanceTrack 150 对）。但单卡 8 GB 上**第二个 GPU worker 直接 OOM**（`BFCArena ... 269746176`）；`--jobs 2` 在单序列网格上只降 7% 墙钟，却让单帧延迟 443.7 → 641.9 ms、显存 4.2 → 6.5 GB。
- **启发**：**并行要按资源种类分工**——GPU 只跑 1 worker，其余并行放 CPU 侧（评测、指标、数据加载）。**"任务并行"在显存受限时会变成"互相拖慢"。**

### 6.4 ✅ 特征规格戳（spec stamp）

- **用法**：`EMBED_SPEC_VERSION` + 权重 basename + `imgsz` 一起写进 summary（`yolo26n-reid.onnx@imgsz448@v2`）。
- **为什么**：特征跨分辨率/权重混用时 A/B 不可比，而结果是**静默的**。
- **启发**：**任何缓存/复用特征的系统都要给特征打规格戳。**
