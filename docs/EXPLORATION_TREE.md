# 整个探索过程：一棵树

> 把 69 个实验、905 次运行压缩成一棵树。**每个节点是一个"我们曾以为可行的方向"，每条边标注它是怎么被证实或剪掉的。**
>
> 符号：**✅ 采用并生效** ｜ **⚠️ 局部有效/有代价** ｜ **❌ 剪枝（实测否决）** ｜ **🔄 结论被自己后来的对照推翻**
>
> 数字均来自实际运行；实验编号以 `docs/EXPERIMENTS.md` 为准（那里有逐条协议与命令）。
> 配套阅读：`docs/REPORT.md`（按方法组织，含文献）、`docs/METHOD.md`（评测协议）。

## 0. 怎么读这棵树

树的**根**是目标，**第一层**是"瓶颈可能在哪"，**第二层**是"用哪类手段"，**叶**是判决。

三个值得先看的动作：

1. **看节点数量**：8 个第一层分支里，只有 3 个（检测换模型、拒识、评测口径）真正产生了指标收益。**其余 5 个分支的主要产出是"此路不通"的证据。**
2. **看 ❌ 的密度**：第二层 47 个手段里，**31 个被剪掉**。剪枝率 66%。
3. **看 §4 三次自我推翻**：有 3 个曾经"成功"的分支后来被自己的对照砍掉——那三次是整棵树里信息量最高的地方。

## 3. 被剪掉的枝，按"为什么剪"归类

这是整棵树最可复用的部分——**31 个死路可以归成 5 类病因**。

### 3.1 前提不成立（方法没错，场景不对）：7 条
| 手段 | 它要求的前提 | 我们的实际 |
|---|---|---|
| 切片推理 SAHI | 目标只有十几像素 | 1280 下 200+ px |
| 步态/姿态身份 | 跨帧序列 + 受控行走 | 单帧 + 任意姿态 |
| 更大通用检测器 | 目标分布与 COCO 一致 | 只有"人"这一类 |
| 特征白化 | 特征里存在冗余维度 | 512-d 小特征，主成分即身份 |
| 外观引导 MOT | 外观判别力足够 | 同着装 AUC 0.59–0.67 |
| 外部 MOT tracklet | 我们需要时它稳定 | 稳定处不需要，需要处每 2–3 帧断 |
| 时间衰减作为收益 | 序列长到会发生遗忘 | 200–300 帧内基本不衰减 |

### 3.2 信息本来就不含（不是调参能救）：5 条
降阈值（边际精度 0.553）· 更多检测器（union 召回 0.830 但 HOTA −1.1pp）· 时序累积（背景最时序一致）· 邻域结构（AUC 0.333）· 运动带（联合位移恰为 0）

### 3.3 自指参考（判据本身被污染）：4 条
| 手段 | 自指的地方 |
|---|---|
| EMA 作第二见证 | 跟着错人时 EMA 就是冒名者（否决 31/31 次正确切换） |
| 自适应遗忘 | "漂移"由 EMA 与图库的关系定义 |
| 运动带自适应 | 用目标自身运动历史定带 |
| 单用近期外观判"变了" | 与"换人了"不可分 |

### 3.4 代价交换而非改进：4 条
管道速度（FAR −32pp 换 TSR −19.5pp）· 冻结天花板（一条序列 +8.4pp，另一条 −11pp）· 单候选守卫（−3.6pp 换 0 收益）· 外观引导关联（11.7× 代价换 0）

### 3.5 机制根本没被触发（"惰性"≠"无害"）：11 条
图库质量门 · 固定锚点 · 自适应遗忘 · 运动带 · 轨迹形状（0007）· 搜索侧若干旋钮（在无搜索的序列上）· 时间衰减 300 vs 600 …
它们的共同点：**消融结果"无变化"被误读成"机制无效"，实际是"机制没运行"。** 必须用计数器证明触发。

## 4. 三次自我推翻（树里最重要的三个 🔄 节点）

### 🔄 R1：「部件描述子有害」
- 曾经的结论：分部件后检索 0.672 → 0.588（更差）
- 推翻方式：发现那个网格在跟踪一个 **38×54 px、检测器从未触达**的目标
- 修正后：**0.672 → 0.855**
- 教训：**先验证探针本身看的是对的框**，再谈方法好坏。

### 🔄 R2：「错误帧上真目标外观排第二（74/111）」
- 曾经的结论：外观证据不可靠
- 推翻方式：探针用 `seq.gt_at(i)[0]` 取真值，那是**该帧任意一个人**（内部稠密 id）
- 修正后：113 个错误帧里 **108 帧目标其实被检测到了**
- 教训：**真值必须走唯一入口**（`make_target_gt`）。

### 🔄 R3：「dev 上 TSR 0.512 / FAR 0.280，指标②接近达标」
- 曾经的结论：7 个旋钮上线，dev 从 0.2228 → 0.512
- 推翻方式：留出 22 序列 + cluster bootstrap
- 修正后：**TSR 0.2102 [0.115, 0.325] / FAR 0.2364**，dev 值落在 CI 之外
- 教训：**在样本数 <10 的数据上选参，就不能用同一批数据报告**。

## 5. 如果重来一次：剪枝后的最优路径树

把 31 个 ❌ 全部剪掉、只保留 ✅ 与两条 ⚠️ 旋钮，这棵树会短到可以一页看完：

```
目标
├─ 检测：换人体专项小模型 @1280                                      （2 个实验）
├─ 评测：先接 MOT ignore 约定 + 自研 HOTA 对拍 + 留出集             （3 个实验，收益最大且免费）
├─ 关联：两阶段 → 边际拒识 → 搜索门控 → 硬负样本(IoU≤0.3,cap8) → 自适应带
├─ 外观：部件感知图库 + 形状偏差门控（只在部分视图触发）
├─ 运动：IMM+NSA + 回滚 + 速度钳制 + 门控归一化
├─ 记忆：双时间尺度 + 盲区冻结
└─ 性能：去重复编码 + 直调 session.run
```

**大约 15 个实验可拿到本项目 90% 的成果**；其余 54 个实验的价值全在"证明不该走"。

如果经费/时间有限，正确顺序是：
1. **先建评测**（ignore 约定、HOTA 对拍、留出集、cluster bootstrap）——占 5% 工作量，决定后面 95% 的结论是否可信。
2. **再做归因诊断**（检测 vs 门控 vs 关联，`probe_gating`）——决定力气往哪投。
3. **然后才调策略**，且先做"拒识"类（收益密度最高）。
4. **最后做性能优化**（−42.8% 是白拿的，不需要任何精度代价）。

## 6. 一条主线（把树压成一句话）

> **检测层的瓶颈是"任务定义"而不是"模型大小"；关联层的瓶颈是"该不该认"而不是"认得多准"；身份问题的根本困难是"没有一个在失败之前就存在的外部参考"——所有自指证据都会在失败后与被检测的错误同向，所以唯一可靠的锚点是点击瞬间那张裁剪，而它只能当旋钮、不能当默认。**
