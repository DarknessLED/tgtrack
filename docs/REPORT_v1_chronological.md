## 1. 任务定义

用 ultralytics YOLO26 做人体检测与 ReID，实现 **DJI ActiveTrack 式"点击跟踪"**：

1. **检测所有人**，但**只跟踪被点击选中的那个人**；
2. 选中目标需要**长期 + 短期 ReID**；
3. 目标**只露出一部分**（上半身/下半身/脸/躯干）时仍能跟踪；
4. 其他行人只需**身份区分**，不需要精确跟踪；
5. 处理**长/短期出画**、**快速运动**、**非线性运动**；
6. **禁止模型微调**，只优化策略与推理管线；允许并行实验。

**关键设计判断**：MOT 跟踪器优化"覆盖率"，ID 短暂错误只要能重新接上就可以接受；而无人机点击跟踪**绝不能跟丢那一个人，也绝不能悄悄换成别人**——错误的锁定在操作员发现之前是**不可见的**。后面的设计都围绕这一点。

## 2. 系统架构

```
视频帧
  ├─ PersonDetector        YOLO26 人体检测（yolo26m@1280 或 CrowdHuman 专项）
  ├─ AllPersonTracker      全体人 MOT 层（6 个后端可选），只负责"别人是谁"
  └─ TargetTracker         单目标层（本项目核心）
        ├─ 两阶段关联      几何粗筛 → 只对幸存者编码外观
        ├─ MotionModel      IMM（cv/ca/ct 三模型）+ NSA 自适应噪声 + 回滚
        ├─ ShortTermMemory  EMA（被证明不可信，见 §6）
        ├─ LongTermGallery  部件感知 + 质量/多样性/时衰减 + 硬负样本
        └─ 状态机          tracking → occluded_soft → lost_short → lost_long → out_of_frame → gave_up
```

**核心机制（真正起作用的四个）**

1. **两阶段关联**：几何先筛（便宜），只对幸存者跑 ReID（在 448 分辨率下编码 20 人×5 部件 ≈ 107 ms/帧，不可行）。实测编码器占墙钟 79%。
2. **部件感知长时图库**：按 `full/upper/lower/head/torso` 分库，用垂直/水平重叠度算查询部件与库部件的亲和度。**这是部分视图能力的来源**：下半身被遮挡时，整身描述子 cos=0.757，而部件查询能给出 upper=0.920 / head=1.0 / torso=0.941，同时把旁人压到 0.48。
3. **拒绝是一等公民**：`select_candidate` 有四个拒绝条件（代价过高、边际不足、单候选无保障、证据不可读）。宁可报"丢失"也不猜。
4. **盲区冻结外观记忆**：丢失期间不吸收新外观，否则会"把遮挡者当成目标"，越跟越自信。

## 4. 实测结果

### 4.1 all-person MOT（指标①）

MOT17，7 序列，subsample 3，200 帧，`--ignore-regions`（按 MOT 官方约定排除 ignore 区域）：

| 检测器 / 跟踪器 | HOTA | MOTA | IDF1 | ms/帧 |
|---|---|---|---|---|
| yolo26m@1280 + tracktrack | 0.4980 | 0.4950 | 0.6125 | 49.7 |
| **CrowdHuman 专项 + tracktrack** | **0.5050** | **0.5586** | **0.6531** | 41.9 |
| 双检测器融合（union recall 0.830） | 0.4944 | 0.4954 | 0.6268 | 89.2 |

**检测器是唯一有效的杠杆**：把 21.9 M 的通用检测器换成 **3.01 M 的 CrowdHuman 人体专项**，pooled recall **0.731 → 0.803（+7.2 pp）**，参数少 7.3 倍，HOTA +0.70 pp、MOTA +6.4 pp、IDF1 +4.1 pp。

DanceTrack val（150 对，subsample 2，no-embed）：tracktrack HOTA **0.4514**、bytetrack 0.4173、ocsort 0.4084、fasttrack 0.4047 —— **DetA 六者几乎相同（差 0.7 pp），AssA 跨 5.6 pp**，说明这个数据集上变量是**关联**而非检测。

VisDrone（7 序列，subsample 3）：tracktrack HOTA **0.3800**、bytetrack 0.3009。**两个 4K 序列 HOTA = 0.0000**（人只有约 15 px 高，检测器根本没检到，任何策略层都救不回来）——这是航拍视角的诚实上限。

## 6. 什么没有起作用（**这一节最有价值**）

### 6.1 检测侧：四条路全部走到黑

| 尝试 | 结果 | 结论 |
|---|---|---|
| SAHI 切片推理（1×1/2×2/3×2/4×3） | recall 0.721→0.721/0.680/0.521 | **无效** |
| 降置信阈值 0.25→0.01 | recall 0.721→0.911，但每帧检测数 19.1→95.8 | HOTA 只 +0.35 pp，**边际精度仅 0.55** |
| 更大检测器 yolo26l@1280 | pooled recall 0.707 < yolo26m 0.733 | **更差** |
| 原生分辨率 1920 | 0.687（逐点更差） | **更差** |
| 时序提升（SPRT 跨帧累积低分检测） | 提升精度 **20–22%** | **反而选出了静止背景** |
| 双检测器框级融合 | union recall 0.830，但 HOTA 0.4944 | **重复框压垮 DetPr** |
| 分时空隙拼接（gap 30） | HOTA 0.4856→0.4860 | **近乎为零** |

**关键洞察**：召回率过了约 0.80 之后，HOTA 由**检测精度与关联**决定，不再由召回决定。**"加检测"是本项目最昂贵的一条死路。**

### 6.2 身份证据侧：两族全部被测量关闭

**第一族：来自目标自身的近期外观（自指参考）**

| 实验 | 信任的参考 | 结果 |
|---|---|---|
| E025 自适应遗忘 | 图库自身漂移 | 惰性（自指） |
| E032/E032b 额外运动轴 | 目标自身运动历史 | **0.000 联合位移** |
| **E064 双见证审计** | click 锚点 + `stm.current()` | **逐位精确的空操作** |

根因（E064 实测）：`stm.current()` 是**已接受 crop 的 EMA**。一旦跟错，短期记忆**就是那个冒名者**——recent 参考在 0007/0005/0004 上分别否决了 **31/31、23/23、16/17** 次本来正确的切换机会（边际中位数 −0.1445 / −0.1986 / −0.0613），切换数归零。**它只能压制切换，永远无法救回。**

**第二族：外部 MOT 层 tracklet 身份（E069）**

| 量 | 值 |
|---|---|
| 丢失帧中存在 IoU≥0.5 的 MOT 框 | **84.4%** |
| ≥5 帧丢失段中被单 id 端到端锚定 | 6/14 = 42.9% |
| ≥5 帧段内被单 id 锚定的帧 | **108/1113 = 9.7%** |
| 五段 ≥50 帧的长丢失 | **全部未锚定** |

**身份在"已经成功"的地方稳定（中位单 id 连续 103 帧），在"失败"的地方每 2–3 帧断一次——与需求反相关。**

### 6.3 其余被否决的方向

特征白化（AUC 0.75→0.55，**破坏**判别力）· 姿态骨架身份（AUC **0.432**，低于随机）· 邻域人际结构（**0.333**）· 轨迹形状描述子（E059，在 0004 上 TSR 0.415→0.095）· 管道速度航向（0007 FAR −32 pp 但 0004 TSR −19.5 pp）· 外观引导关联（机制证明真的开着后 AssA **−0.068 pp**，代价 11.7×）· Hybrid-SORT 后端（HOTA −1.5 pp）· 图库卫生/自适应遗忘/固定锚点（全部惰性或序列依赖）· 合成数据训练（用户已禁止微调）。

### 6.4 三个被自己的对照"杀死"的结论（重要）

1. **"部件描述子有害"** —— 那个网格在跟踪一个 **38×54 px、检测器从未触达**的目标。重跑后结论反转：0.672 → 0.855。
2. **"外观在错误帧上排第二"（74/111）** —— 探针用 `seq.gt_at(i)[0]` 取真值，那**不是目标**（内部稠密 id 而非 MOT id）。在对齐后：真目标在 **113 个错误帧里有 108 帧其实被检测到了**。
3. **"dev 上 TSR 0.512"** —— 留出集 **0.2102**，落在 95% CI 之外。**dev 三分序列的置信区间是 ±0.394（TSR）和 ±0.708（FAR），从来不曾证明任何事。**

## 7. 方法论教训（12 条，可直接复用）

1. **留出集不是可选项。** 7 个上线旋钮全部"选在 0004/0005/0007，又报在 0004/0005/0007"——**100% 的选择/报告重叠**。n=3 的均值得出的结论在 n=22 上崩塌了 30 pp。**先冻结 dev，任何报告只用留出集。**
2. **"逐位相同"必须逐元素实测。** 把 4 个 crop 拼成 12 个 crop 一起前向，CUDA 卷积就会漂 3.0e-4。性能评审断言"bit-identical"，实现阶段被证伪（虽然决策确实没变）。
3. **自指参考无法为自己作证。** 判据：*这个参考会在它要检测的失败发生之前被写下来吗？* 若否，实验作废。合法参考只有两种：**失败之前捕获的**（click 锚点）、**来自被跟踪者自身历史之外的**。
4. **空开关是最危险的负结果。** "with_reid 无变化"其实是 `--no-embed` 导致特征根本没传播；必须**用计数器证明机制真的开着了**（那次是 14,400 行特征、400/400 帧、最多 60 条轨迹携带特征）。
5. **基准会静默换人。** `dancetrack0005` 曾被自动选成 target id 0 又选成 2，于是"回归 30 pp"其实是换了个人。**任何对比运行都必须显式钉住 `--target-id`，并在表格里记录它。**
6. **改默认值的那一刻，旧数据就不可比了。** 有一次在 A/B 中途改默认，导致新旧数字混用。**epoch 必须显式命名。**
7. **先证明机制被触发，再解释结果。** 审计间隔 15/30 帧全部"无变化"，不是没效果，而是**从根本上不会触发**（置换时标约 10 帧）。改成 5 帧后才看到 +20.3 pp。
8. **一个样本上的大胜不等于可发布。** +20.3 pp（0007）是用 −28 pp（0004）换来的。
9. **多重比较会制造"进展"。** 905 次运行、96 个变体、514 个指标②单元格 → α=0.05 下约 3.5 个假阳性。**上线前先算清搜索空间。**
10. **重复实验应先检查"机制是否活跃"，而不是加深调参。** 图库锚点实验全是惰性——因为 200 帧内图库根本没轮转过。
11. **让外部评审来审计自己的数字。** 24 条声明被独立复算：OK 12 / 过期 4 / **错误 6** / 无支撑 2。包括"3.6 pp 代价"其实没有对照组、"lower 掩码格"抄成了 upper 的数值。
12. **诚实的负结果比漂亮的假数字更可复用。** 本项目的 40+ 个负结果构成了上面这些规则的全部依据。

## 8. 工程陷阱（20 条，全部踩过）

**环境**
1. `torch` 必须从 `--index-url https://download.pytorch.org/whl/cu126` 装，PyPI 上是 CPU 版。
2. 控制台是 **GBK**：所有 python 前设 `$env:PYTHONIOENCODING="utf-8"`，且 `Path.read_text()` 必须显式 `encoding="utf-8"`（否则读 ultralytics 的 yaml 会 `UnicodeDecodeError`）。
3. `huggingface.co` 被墙，`hf-mirror.com` 可用（`HF_ENDPOINT`）；`github.com` 不可达，权重走 `ghproxy.net`。
4. onnxruntime-gpu 报 `cublasLt64_13.dll missing`：版本与 torch 的 CUDA 不匹配，装 CUDA-12 对应版本。
5. Trae 内置的 ffmpeg 是 `--disable-everything` 版，**没有 image2/mjpeg**，换用完整版。
6. 8 GB 卡上**只能一个 GPU worker**；第二个 worker 会触发 `BFCArena ... 269746176` OOM。
7. `--jobs 2` 只把网格墙钟降 7%（启动重叠），但单次延迟 443.7→641.9 ms/帧、显存 4.2→6.5 GB。

**接口**
8. `--trackers a.yaml b.yaml` 会报错，必须是**逗号分隔的一个值**。
9. `--ablate` 默认**是 `"all"`**（84 个变体，10 帧就 450 s），且 `build_variants("")` 也映射到 `"all"` —— **CLI 无法表达"只跑 baseline"**。
10. `eval_mot.py` 默认 `--no-embed`，而 `MotCfg.with_reid` 默认 True，两者相差 2.6 pp。
11. `run_target.py` 的 `RunOptions` 是逐字段构造的可 pickle dataclass：**新增 argparse 旗标必须同时加字段**，否则 `getattr(opts, x, False)` 静默为 False（曾连续 3 次"旗标无效"）。
12. 检测器 `imgsz` 必须与权重训练分辨率一致；ReID 有 `spec` 戳（`yolo26n-reid.onnx@imgsz448@v2`）防止跨分辨率混用特征。
13. `half` 参数在 ultralytics 8.4.185 已弃用，实际对 fp32 ONNX 是空操作——**不要宣称 fp16 生效**。

**测量**
14. **GT 索引陷阱**：`GtBox.track_id` 是装载器内部稠密 id，**不是 MOT id**；`seq.gt_at(i)[0]` 是"该帧任意一个人"。真值必须走 `make_target_gt(seq, target_id)`。这个 bug 造成了两次结论撤回。
15. 掩码语义要读源码确认：只有目标自己的框被裁成可见矩形，其他人保留原框（只是降低可见度），遮挡物还会外扩以避免压到可见矩形。
16. `n_report_frames` 不是帧轴；CSV 的轴是 0..N-1 的处理后帧号。
17. 跨管线对比必须**验证逐帧对齐**（用 `gt_xyxy` 与 `make_target_gt` 逐帧比对 + 滞后检验），不能假设。
18. 朴素 argmax 归属会**伪造 id 切换**（曾虚构 21 次），要用贪心延续匹配。

**性能**
19. `_features_for` 会**重复编码** `_ensure_features` 刚算过的框（94 ms/帧，占总墙钟 33%）。
20. `_ensure_features` 会**吞掉编码器异常**，编码器坏掉时静默退化成纯几何跟踪（这让性能剖析第一次读出"编码器只占 2%"）。现在计入 `stats()["encoder_errors"]`。
